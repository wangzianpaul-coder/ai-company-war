## Architecture Boundary

- Every new production type uses typed GDScript and extends `RefCounted`; none is a Node, Resource, Scene, Autoload or singleton.
- All money is signed integer cents with `_cents` names. No finance/project formula uses float.
- `CompanyState` contains only cash, monthly revenue and monthly operating cost. Cash may be signed; revenue and costs must be non-negative.
- `ProjectState` represents one project slot only. It has a stable `StringName` ID, NOT_STARTED/ACTIVE/COMPLETED lifecycle, required/progress integer months, non-negative monthly cost cents and non-negative completion monthly-revenue delta cents.
- Test fixture numbers are verification inputs, not product balance constants or Content definitions.
- `EffectContribution` is getter-only typed data with stable source/reason/subject/metric keys, an explicit CENTS or MONTHS unit and a signed integer delta. It has no Dictionary, Variant payload or UI text.
- `EffectBatchResult` is getter-only typed data containing success/failure, a small typed error enum and an ordered typed array of contributions. It is not TickResult, CommandResult, DomainEvent or a generic framework.
- `FinanceSystem` atomically settles one month of revenue and operating cost. It emits separate non-zero gross contributions in stable order; it must not replace them with one unexplained net delta.
- `ProjectSystem` validates/starts the one project and atomically advances at most one month. An active month charges project cost once, increments progress once and applies a completion revenue delta at most once.
- Completed projects do not progress, charge cost or emit zero/fake contributions on later calls.
- On invalid state or int64 overflow/underflow, each individual system call returns typed failure and changes neither state nor effects.
- `GameState` retains its clock and owns typed CompanyState and exactly one typed ProjectState. Separate GameState instances do not share mutable state.
- Production systems never advance the clock and never orchestrate each other. Only the unit test composes three explicit `Project → Finance → Clock` steps.
- `simulation/` does not depend on `application/`, `ui/`, `persistence/`, tests, SceneTree, Time, OS, FileAccess, frame delta or random APIs.
- Do not add a SimulationEngine, GameSession, concrete GameCommand, dispatcher, event bus, undo system, save DTO, Content Resource or UI signal.

## Acceptance Criteria

- All six new production classes are typed `RefCounted` objects and respect the dependency boundary.
- Default `GameState` remains January 2026 / Q1 and owns non-null, independently allocated typed clock/company/project objects.
- Finance uses integer cents and computes the exact checked monthly cash change from revenue and operating cost.
- Non-zero revenue and operating cost produce separate ordered contributions; `cash_before + sum(cash contribution deltas) == cash_after`.
- When non-zero revenue equals non-zero operating cost, cash is unchanged but both real gross contributions remain explainable; zero components emit no fake zero contribution.
- A valid active project advances exactly one integer month and charges its monthly cost exactly once.
- A project completes exactly at `required_months`, never over-progresses, and applies its completion monthly-revenue delta no more than once.
- A completed project is a stable no-op on later advance calls: no cost, progress, benefit or zero contribution is produced.
- Invalid IDs/durations/progress/costs and checked int64 overflow/underflow return typed failure with no partial state change and no effects.
- Every contribution field is derived from the same actual mutation and ordered deterministically.
- The test-only Golden Case starts with cash `1_000_000` cents, revenue `120_000`, operating cost `80_000`, a three-month project costing `25_000` per month and adding `30_000` monthly revenue at completion.
- Three explicit test-composed months finish at April 2026 / Q2, project `3/3 COMPLETED`, monthly revenue `150_000` cents and cash `1_075_000` cents, with every ordered effect reconciled.
- Two equivalent typed initial states running the same three-month sequence produce equal fields and an equal ordered effect trace; the trace also matches the fixed Golden Case, not only the other run.
- Existing TP-010 clock/command/result tests and M0 scene/button tests continue to pass.
- `project.godot`, `main.gd` and `main.tscn` retain their known SHA-256 hashes.
- Only whitelisted files and generated UIDs differ.
