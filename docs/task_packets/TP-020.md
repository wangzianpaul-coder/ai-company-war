## Architecture Boundary

- `SetComputeAllocationCommand` directly extends GameCommand and contains exactly one typed integer value/getter: `training_units_per_month`.
- ComputeState is typed RefCounted with non-negative integer units: total, reserve, inference workload, current training allocation, and cumulative training/served/unmet compute-unit-months.
- Reserve ≤ total and training ≤ total-reserve. Inference allocation is derived as the remaining allocatable capacity; UI never derives it.
- A valid zero/default ComputeState is inert so every old fixture retains the exact 13-effect trace.
- ComputeSystem is pure Simulation RefCounted code with checked signed-64 arithmetic and existing typed EffectBatchResult output.
- Per-month effect order is training work, served inference, optional unmet inference. Zero effects are omitted; metadata and units are exact.
- Compute is monthly flow: nothing carries into later months or becomes cash, inventory, hardware, servers, chips or power.
- Allocation and quarter operations begin from a full independent GameState copy.
- Quarter order becomes exactly `Project → Compute → Finance → Clock` three times. Any failure discards the full candidate state/effects.
- GameSession accepts exactly three concrete command scripts. Allocation success replaces state, clears command effects, replaces ViewModel, then emits exactly once; rejection changes nothing.
- DashboardViewModel stays primitive-only. Dashboard depends only on GameSession, ViewModel, three command scripts and UI types. It submits an integer command and never imports State/System/Engine/Effect or computes capacity.
- Compute explanations aggregate only the committed ordered contributions.
- main remains Composition Root; Simulation gains no Node/UI/IO/time/frame/random/Persistence dependency.
