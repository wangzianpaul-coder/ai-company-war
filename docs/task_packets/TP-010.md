## Goal

Prove the first G1 architecture seam with a minimal, deterministic, pure-GDScript domain foundation:

- a typed `RefCounted` simulation clock whose base unit is one month;
- exactly three explicit month advances per quarter and correct year rollover;

- domain-owned typed `GameCommand` and `CommandResult` boundary skeletons for later Application use;
- headless unit coverage registered through the existing M0 runner.

This TP does not implement finance, projects, SimulationEngine, GameSession or UI integration.

## Architecture Boundary

- New domain/state/command/result types use typed GDScript and extend `RefCounted`; they are not `Node`, `Resource`, Autoload or Scene objects.
- `GameCommand` and `CommandResult` are owned by `simulation/commands/`; Application may depend on them, while `simulation/` must never depend on `application/`.
- `simulation/` must not depend on `ui/`, `persistence/`, `SceneTree`, `Time`, `OS`, `FileAccess`, frame delta or random APIs.
- `GameState` may own the clock but must not introduce cash, revenue, cost, projects, markets, opponents, events, save DTOs or content definitions.
- The clock's base unit is an integer month. Quarter display/derivation is deterministic; no float or system time.
- Public state is not represented by one unstructured `Dictionary`.
- Command/Result are only typed boundary skeletons in this TP; do not invent a command bus, dispatcher, event bus, undo system or application service.
- The existing UI remains the current Composition Root prototype and must not reference the new domain files yet.

## Acceptance Criteria

- The new domain classes are typed `RefCounted` objects and have no Godot scene/UI/file/time/random dependency.
- A default clock represents January 2026 / Q1 using explicit integer fields or equivalent typed accessors.
- One month advance moves January to February without changing quarter.
- Three month advances from January 2026 produce April 2026 / Q2.
- Twelve month advances from January 2026 produce January 2027 / Q1.
- Repeating the same valid advance sequence from equal initial state yields equal typed values.
- Boundary/invariant behavior is explicit and tested; a failure must not leave partially advanced state.
- `GameState` owns or references the typed clock without introducing TP-011/TP-012 fields.
- `GameCommand` and `CommandResult` provide a minimal typed seam without unstructured public payloads or unused framework machinery.
- The M0 scene/UI tests still pass unchanged in behavior.
- Only whitelisted files and generated UIDs differ.
